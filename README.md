# Тестовое задание — AI-генератор карточек товаров

REST API с веб-интерфейсом для автоматической генерации SEO-описаний и структурированных карточек товаров на основе технических характеристик с использованием LLM.


## Стек

- Python 3.12
- FastAPI + Pydantic
- Groq API (`openai/gpt-oss-120b`)
- Docker + Docker Compose

## Локальный запуск

### 1. Клонировать репозиторий

```bash
git clone <repository-url>
cd product_description_generator
```

### 2. Создать и активировать виртуальное окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Для Windows:

```bash
.venv\Scripts\activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Настроить переменные окружения

Создать файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Указать API-ключ Groq и используемую модель:

```env
GROQ_API_KEY=groq_api_key
GROQ_MODEL=openai/gpt-oss-120b
```

### 5. Запустить приложение

```bash
uvicorn app.main:app --reload
```

После запуска веб-интерфейс будет доступен по адресу:

`http://localhost:8000`

Swagger:

`http://localhost:8000/docs`

## Запуск через Docker

Создать `.env` на основе `.env.example` и указать API-ключ Groq.

Для сборки и запуска приложения:

```bash
docker compose up --build
```

После запуска приложение будет доступно по адресу:

`http://localhost:8000`

Swagger:

`http://localhost:8000/docs`

Для остановки:

```bash
docker compose down
```



Примеры входных данных находятся в директории `examples/`.

## Тесты

Для запуска тестов:

```bash
python -m pytest -v
```

Реализованы модульные и API-тесты, проверяющие:

- Успешную генерацию карточек.
- Повторные попытки при нарушении ограничений.
- Сохранение исходных характеристик.
- Обработку ошибок API.

В тестах используются моки.

## Принятые решения

Для генерации карточек используется Groq API с асинхронным клиентом. Логика разделена на отдельные компоненты: API, LLM-клиент, генератор, промпты и валидаторы.

Для снижения вероятности появления недостоверных характеристик используются ограничения в промпте. Исходные технические характеристики сохраняются программно, без изменений со стороны LLM.
Проверка длины seo-описания выполняется на стороне Python. Если результат не соответствует ограничениям, генератор делает одну повторную попытку с передачей информации об ошибке.


## Что можно было бы добавить

При наличии доп. времени можно было бы реализовать более строгую проверку фактической достоверности сгенерированных описаний, пакетную генерацию карточек и кеширование результатов.

Для production-сценария также можно добавить PostgreSQL для хранения истории генераций, Redis и Celery для фоновой обработки больших объёмов товаров, авторизацию и мониторинг.
